# Documentation Guidelines

## Language

All repository documentation must be written in **English**.

This applies to:

- README files.
- Architecture documentation.
- ADRs.
- Roadmaps and tracking guides.
- Runbooks.
- Deployment guides.
- Testing documentation.
- Security documentation.
- Operational documentation.
- Inline documentation intended for repository readers.

Code identifiers, API names, AWS service names, commands, configuration keys, and other technical identifiers should remain in their canonical form.

When documenting a concept, prefer clear technical English over literal translations of terminology.

## Scope

This language convention applies to documentation committed to the repository. It does not restrict:

- source-code identifiers;
- user-facing product copy when the product explicitly requires another language;
- test fixtures whose content intentionally represents another language;
- external communication such as GitHub comments or pull request discussion.

## Consistency

New documentation should follow the language and terminology already established in the repository.

When adding a new documentation file, review it before opening a pull request and confirm that its prose is entirely in English.

## Why

The project is intended to serve as a technical portfolio and Cloud Engineering learning lab. Keeping the repository documentation in English makes the architecture, operational practices, ADRs, and engineering decisions directly usable as professional technical material.
